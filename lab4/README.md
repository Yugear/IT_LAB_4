## Назначение файлов

- `inventory.py` — формирует `passport_<имя_ПК>.json` (система, CPU, RAM, диски, сеть) и рекомендации по состоянию ПК.
- `monitor.py` — делает замеры CPU, RAM, DISK, записывает дополнительную метрику своего варианта, формирует предупреждения и статистику (среднее, минимум, максимум).
- `monitor_log.csv` — создаётся при запуске `monitor.py` (измерения вашего ПК, поэтому файл не включён заранее).
- `passport_<имя_ПК>.json` — создаётся при запуске `inventory.py` (у каждого компьютера свой).
- `requirements.txt` — зависимости проекта.
- `Отчет_варианты_3_4_5.docx` — шаблон краткого отчёта в ZIP-архиве, добавьте свои скриншоты и реальные результаты.

## Параметры вариантов (из задания, стр. 5)

| Вариант | INTERVAL (с) | SAMPLES | Порог CPU / RAM / DISK | Дополнительная метрика |
|---|---:|---:|---|---|
| 3 | 3 | 15 | 80 / 80 / 85 % | `network_sent_mb`: отправлено по сети, МБ |
| 4 | 1 | 40 | 60 / 75 / 80 % | `battery_percent`: заряд батареи, % |
| 5 | 2 | 25 | 85 / 90 / 95 % | `network_recv_mb`: получено по сети, МБ |

**Важно:** значения сетевых счётчиков — суммарные с момента загрузки ОС, а не скорость передачи. МБ вычисляются как `bytes / 1024**2`. Если устройство не имеет батареи, в варианте 4 отображается `N/A` и в CSV остаётся пустое значение.

## Пример вывода (условные числа, не результаты измерения вашего ПК)

Итоговая статистика:

## Задание 5 — проверка узкого места

1. Откройте **два** терминала в папке проекта.
2. В первом запустите `python monitor.py --variant 3` (или 4, 5).
3. Во втором создайте нагрузку на **одно ядро CPU**: `python -c "while True: pass"` и завершите `Ctrl+C`.
4. Для эксперимента с памятью используйте команду из задания:
   `python -c "a = bytearray(2 * 1024**3); input('Нажмите Enter...')"`
5. Перед тестом RAM убедитесь, что 2 ГБ **не превышают половину физической RAM** и памяти действительно хватает. При сомнении замените `2` на `1` или пропустите эксперимент. Дождитесь полного цикла замеров и проанализируйте CSV.
6. Ответьте, какая метрика **фактически** первой достигла своего порога: это нельзя достоверно определить без запуска программы на вашем компьютере.

Один процесс с циклом `while True` обычно загружает лишь один логический процессор. Если логических процессоров `N`, вклад одного полностью занятого потока в общую загрузку приблизительно `100/N` процентов (при прочих простаивающих).
